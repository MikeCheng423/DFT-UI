## 1. Build POTCAR on the remote — `runner.py`, `cli.py`

**Why:** for `ssh_detached` offload runs the engine already builds INCAR/KPOINTS
on the remote, but the POTCAR was always built **locally and shipped**. That ties
every offload to a local POTCAR library and means "inputs created on the remote"
wasn't fully true.

**What changed:**

- `submit_job_detached` writes `potcar_root:` into the remote `config.yaml` when
  the remote config has one, so the remote engine's existing
  `_copy_or_build_potcar` builds the POTCAR there (it already builds when the
  shipped case has no POTCAR).
- `_run_detached_offload` skips the local `build_potcar`/ship when the machine has
  a `potcar_root`; otherwise it pre-builds and ships exactly as before (the
  fallback for machines with no library).
- `remotes.json.example` documents the optional `potcar_root` field. Library
  layout must be `<potcar_root>/<Element>/POTCAR` (potpaw style).

**Verified:** each remote venv's `build_potcar` produces a POTCAR from its own
library (apl2 `Au`→227 KB; tlclab `Au,C,Sn`→650 KB). Runner + remote-setup tests
pass (56), full suite 423 passed / 1 skipped.

**Not done:** `potcar_map` (pseudopotential variant selection) is *not* forwarded
to the remote build yet — flagged with a `ponytail:` comment in
`submit_job_detached`. No config currently sets one; add it there if that changes.

## 3. Why detached runs "collapse" on tlclab — diagnosis + fixes

**Root cause:** not the detach mechanism. A detached heartbeat *and* a real
`mpirun` both survive an SSH disconnect/logout on both machines. tlclab is a
**WSL2 instance on a shared Windows desktop (TLCLAB)**; its jobs die when the host
**suspends/resumes** (run.log ends with `mpirun: Forwarding signal 18 to job` —
SIGCONT on wake — then no `rc`; WSL2 interop also breaks until `wsl --shutdown`)
or when the **WSL-owner logs off** (the VM is torn down). apl2 is native Linux
with multi-week uptime and every job completes.

**Fixes applied / prepared:**

- **Never sleep** — `powercfg` standby-timeout AC+DC = 0, lid = do-nothing,
  hibernate off. (The first attempt didn't survive a reboot, so it's folded into
  the keepalive script below.)
- **Survive logoff** — wrote `C:\Users\Public\KeepWSL2Alive.ps1` on TLCLAB
  (also `~/KeepWSL2Alive.ps1`). It sets the power settings and registers a
  scheduled task `KeepWSL2Alive` (AtStartup + AtLogon, S4U "run whether logged on
  or not", Highest, auto-restart) whose action `wsl.exe --exec tail -f /dev/null`
  holds the WSL2 VM up 24/7. `tailscaled` + `sshd` run inside the VM and are
  boot-enabled, so SSH/Tailscale stay reachable across logoff.
